## 1. 튜너를 만들어보자
### -개요
&nbsp;==튜너==는 악기의 주파수를 기반으로 음정의 높낮이를 측정하여 조율 악기가 정확한 음을 낼 수 있게 하는 역할을 합니다. 이번 게시물에서는 ==Web Audio API==를 이용하여 사용자의 오디오 입력을 받아 해당 신호의 주파수를 분석하고, 이를 기반으로 현재 연주 중인 음의 음정을 계산하는 기능을 만들어 보겠습니다.

### -초기 설계
&nbsp;튜너 기능을 포함하는 `AudioContext`의 구성은 생각보다 단순합니다. 이전 게시물에서 연결한 
`[MediaStreamAudioSourceNode] → [ChannelSplitterNode] → [GainNode] → [ChannelMergerNode] → [destination]` 의 구조에서, 출력에 필요한 `ChannelMergerNode`와 `destination`으로의 연결은 제거하고, 대신 가장 마지막에 주파수 분석 노드를 연결하면 됩니다.

초기 설계 단계에서는 ==Web Audio API==의 `AnalyserNode`를 사용하려 했으나, 해당 노드는 ==주파수 분포 시각화==에는 적합하지만, 실시간 신호 처리 및 분석에는 부적합하다고 판단되어, `AudioWorkletNode`를 이용하여 직접 노드를 제작하고, 이를 `AudioContext`에 연결하고자 하였습니다.

## 2. AudioWorkletNode
### -AudioWorkletNode란
&nbsp;==AudioWorkletNode==는 사용자가 직접 정의한 오디오 처리 로직을 실행하는 저수준 노드입니다. 이를 통해 우리는 원하는 방식으로 오디오 데이터를 읽고, 계산하며, 가공할 수 있습니다.

이 노드는 ==AudioWorkletProcessor==이라는 객체와 한 쌍으로 작동합니다. 각각의 역할은
- AudioWorkletNode: 메인 스레드 (JS 실행 환경)
- AudioWorkletProcessor: 오디오 렌더링 스레드(실시간 오디오 처리 전용 환경)

이 둘은 ==port==를 통해 메세지를 주고 받을 수 있습니다. 

즉, 실질적인 오디오 데이터는 렌더링 스레드(==AudioWorkletProcessor==)에서 처리되고, 그 결과(주파수 등)가 메인 스레드(==AudioWorkletNode==)로 전달되어 UI나 시각화에 사용할 수 있습니다.

그렇기 때문에 우리는 ==AudioWorkletProcessor==를 먼저 생성한 후, 이를 기반으로 ==AudioWorkletNode==를 생성해야 합니다.

자세한 사용법은 후술하겠습니다.

### -AudioWorkletProcessor제작
&nbsp;==AudioWorkletNode==와 통신하는 ==AudioWorkletProcessor==는 웹팩의 번들링 결과물에 포함될 수 없습니다. 왜냐하면 이 파일은 메인스레드에서 직접 `import`되는 게 아니라 오디오 엔진이 `fetch()`형태로 직접 요청을 보내서 로드하기 때문입니다.
따라서 정적 경로를 확보하기 위해, 우리는 ==public==폴더 안에 ==AudioWorkletProcessor==를 담는 파일을 생성해야 합니다.

> public/worklets/PitchProcessor.js
```ts
class PitchProcessor extends AudioWorkletProcessor {
  constructor() {
    super();
    .
    .
    .
  }

  process(inputs, outputs, parameters) {
    this.port.postMessage({ message });
  }
}

registerProcessor("pitch-processor", PitchProcessor);
```

==AudioWorkletProcessor==의 토대입니다. 각 줄은 다음과 같은 의미를 갖습니다.

- `class PitchProcessor extends AudioWorkletProcessor` : 오디오 처리 전용 클래스 정의. 모든 커스텀 워크렛은 이 클래스를 상속해야함.
- `process(inputs, outputs, parameters)` : 오디오 버퍼가 들어올 때마다 자동 호출되는 메서드. 실시간 데이터 처리.
- `this.port.postMessage()` : 메인 스레드(AudioWorkletNode)로 메세지를 전달하는 통신 메서드.
- `registerProcessor("이름", 클래스)` : 브라우저에 이 클래스를 워크렛으로 등록. 이름은 나중에 ==AudioWorkletNode==를 생성할 때 사용.

이제 이곳에다 오디오 신호를 분석하고 주파수를 출력하는 함수를 넣어 튜너를 만들어보겠습니다.

## 3. 튜너 제작
### -오디오 신호 축적
&nbsp;먼저, 앞서 설명한 `process(inputs)`는 브라우저로부터 128프레임 단위의 매우 짧은 오디오 데이터를 받습니다. 이렇게 짧은 신호로는 피치를 안정적으로 감지할 수 없기 때문에, 데이터를 일정 길이만큼 축적해놓았다가 이를 분석해야합니다.
```ts
constructor() {
    super();
    this._buffer = new Float32Array(2048);
    this._offset = 0;
  }
```
이렇게 해서 데이터를 일정길이(2048 샘플)만큼 저장할 수 있게끔 속성을 선언해두고, 

```ts
process(inputs) {
    const input = inputs[0][0];
    if (!input) return true;

    this._buffer.set(input, this._offset);
    this._offset += input.length;
```
이와 같이 오디오 버퍼가 들어올 때 마다 `_buffer`에 저장합니다(`_offset`은 현재 버퍼가 얼마나 채워졌는지 추적하는 포인터). 이후 `_buffer`에 저장된 데이터를 분석하면 됩니다.

### -YIN 알고리즘
&nbsp;==YIN 알고리즘==은 대표적인 피치추정 기법으로, ==자기상관함수==를 기반으로 “파형이 일정 주기로 얼마나 비슷하게 반복되는가"를 계산하여 주기성을 찾고 이를 통해 기본 주파수를 찾아 신호의 피치를 얻는 알고리즘입니다.

다음은 해당 알고리즘을 함수로 구현한 코드입니다.

> public/worklets/PitchProcessor.js/yin
```ts
function yin(buffer, sampleRate = 44100, threshold = 0.15) {
  const bufferSize = buffer.length;
  const yinBuffer = new Float32Array(bufferSize / 2);

  // 차이 함수 계산
  for (let tau = 0; tau < bufferSize / 2; tau++) {
    let sum = 0;
    for (let i = 0; i < bufferSize / 2; i++) {
      const diff = buffer[i] - buffer[i + tau];
      sum += diff * diff;
    }
    yinBuffer[tau] = sum;
  }

  // 누적 정규화
  yinBuffer[0] = 1;
  let runningSum = 0;
  for (let tau = 1; tau < yinBuffer.length; tau++) {
    runningSum += yinBuffer[tau];
    yinBuffer[tau] *= tau / runningSum;
  }

  // threshold값 이하의 주파수 탐색 & 반환
  for (let tau = 2; tau < yinBuffer.length; tau++) {
    if (yinBuffer[tau] < threshold) {
      while (
        tau + 1 < yinBuffer.length &&
        yinBuffer[tau + 1] < yinBuffer[tau]
      ) {
        tau++;
      }
      const pitch = sampleRate / tau;
      return pitch;
    }
  }

  return null;
}
```
제가 구현한 코드는 크게 세 부분으로 나눌 수 있습니다. 각각의 부분은 다음과 같은 역할을 합니다.
- 차이 함수 계산: 각 버퍼의 값과 `tau`(시간)만큼 뒤의 값과의 차이의 제곱합을 누적합니다. 만약 `tau`가 실제 음의 주기라면, 차이가 매우 작아지게되고, 이는 `tau`가 그 신호의 주기일 가능성이 높다는 뜻입니다.
- 누적 정규화: 차이값은 `tau`가 커질수록 자연히 커지기 때문에(비교 구간이 길어짐), 이것을 보정하기 위해 정규화를 수행합니다. 큰 `tau`에서도 작은 `tau`와의 공평한 비교를 위해, `yinBuffer[tau]`를 누적 평균으로 나눠서 `tau`의 크기에 따라 차이값의 왜곡을 제거합니다.
- threshold값 이하의 주파수 탐색: 정규화된 `yinBuffer[tau]`는 0에 가까울 수록 "비슷한 패턴"(주기)이라는 뜻입니다. 따라서 일정 기준(threshold) 아래로 내려가는 첫 번째 구간을 찾아내면 그때의 `tau`값이 바로 주기가 됩니다. 그리고 샘플레이트를 `tau`로 나누면 주파수가 되고, 이는 피치를 의미합니다.

### -노이즈 제거
> public/worklets/PitchProcessor.js/getRMS
```ts
function getRMS(input) {
  let sum = 0;
  for (let i = 0; i < input.length; i++) {
    sum += input[i] * input[i];
  }
  return Math.sqrt(sum / input.length);
}
```
&nbsp;추가로, `input`신호를 기반으로 노이즈를 필터링(바이패스)하는 함수도 생성하였습니다.

==RMS==는 평균적인 음량을 의미하는데, 이것이 너무 작으면 그냥 노이즈이거나 무음이므로, `rms < 0.01`와 같은 조건으로 계산을 스킵하거나 오탐을 방지합니다. 조건문의 값을 변경하면 튜너의 감도를 조절할 수 있습니다.

### -전체 연결
&nbsp;그렇게 완성한 튜너 ==AudioWorkletProcessor==의 코드는 다음과 같습니다.
```ts
function yin(buffer, sampleRate = 44100, threshold = 0.15) {
  const bufferSize = buffer.length;
  const yinBuffer = new Float32Array(bufferSize / 2);

  for (let tau = 0; tau < bufferSize / 2; tau++) {
    // 차이 함수 계산
    let sum = 0;
    for (let i = 0; i < bufferSize / 2; i++) {
      const diff = buffer[i] - buffer[i + tau];
      sum += diff * diff;
    }
    yinBuffer[tau] = sum;
  }

  // 누적 정규화
  yinBuffer[0] = 1;
  let runningSum = 0;
  for (let tau = 1; tau < yinBuffer.length; tau++) {
    runningSum += yinBuffer[tau];
    yinBuffer[tau] *= tau / runningSum;
  }

  // threshold값 이하의 주파수 탐색 & 반환
  for (let tau = 2; tau < yinBuffer.length; tau++) {
    if (yinBuffer[tau] < threshold) {
      while (
        tau + 1 < yinBuffer.length &&
        yinBuffer[tau + 1] < yinBuffer[tau]
      ) {
        tau++;
      }
      const pitch = sampleRate / tau;
      return pitch;
    }
  }

  return null;
}

function getRMS(input) {
  // 노이즈 제거
  let sum = 0;
  for (let i = 0; i < input.length; i++) {
    sum += input[i] * input[i];
  }
  return Math.sqrt(sum / input.length);
}

class PitchProcessor extends AudioWorkletProcessor {
  constructor() {
    super();
    this._buffer = new Float32Array(2048);
    this._offset = 0;
  }

  process(inputs) {
    const input = inputs[0][0];
    if (!input) return true;

    this._buffer.set(input, this._offset);
    this._offset += input.length;

    if (this._offset < this._buffer.length) return true;

    const rms = getRMS(this._buffer);
    if (rms < 0.01) {
      this._offset = 0;
      return true;
    }

    const pitch = yin(this._buffer, sampleRate);
    if (pitch) {
      this.port.postMessage({ pitch });
    }

    this._offset = 0;
    return true;
  }
}

registerProcessor("pitch-processor", PitchProcessor);
```
오디오 인풋으로 신호가 들어오게 되면, `process`메소드가 호출됩니다. 이후 `_buffer`속성에 데이터가 누적되게 되고, `_offset`으로 추론한 누적량이 임계치를 넘으면, 노이즈 필터링을 통해 무의미한 계산을 방지합니다.
이후 `yin`함수를 통해 주파수를 반환 받고, 이 값이 `truthy`한 값이라면 `this.port.postMessage`를 이용하여 메인 스레드로 주파수를 전송합니다.

>`process`내부의 `return true`는 만약 `false`를 반환할 경우 오디오 스트림이 중단되기 때문에 스트림을 지속시켜주는 역할을 수행합니다.

이제 이렇게 만든 ==AudioWorkletProcessor==를 통해 노드를 만들어 연결해보겠습니다.

## 4. 튜너 완성
### -AudioContext 연결
&nbsp;다음은 코드 일부입니다.

>src/utils/tunerUtils.ts/setUpTuner
```ts
  const source = ctx.createMediaStreamSource(stream);
  const splitter = ctx.createChannelSplitter(source.channelCount);
  source.connect(splitter);

  const gain = ctx.createGain();
  gain.gain.value = 10;
  splitter.connect(gain, channel);

  const workletNode = new AudioWorkletNode(ctx, "pitch-processor");
  gain.connect(workletNode);

  workletNode.port.onmessage = (e) => {
    const { pitch } = e.data;
    if (pitch) {
      onPitchDetected(pitch);
    }
  };
```
기본 연결은 이전 게시물에서 설명한 바와 동일합니다. 

다만, ==AudioWorkletNode==를 선언하는 방식은 다소 다릅니다. 먼저, `const workletNode = new AudioWorkletNode(ctx, "pitch-processor");`의 구문으로 ==AudioWorkletNode==를 생성해줍니다. 여기서 생성자 두 번째 파라미터의 이름은, ==AudioWorkletProcessor==를 등록할 때 사용한 이름을 기입하면 됩니다.
이후 앞서 연결한 `GainNode`와 연결해주고, ==AudioWorkletProcessor==에서 `process`시에 전송되는 메세지를 받게되면 수행할 작업을 선언해주면 됩니다. 이 경우 `pitch`값은 주파수이므로, 사용자가 직관적으로 음을 잘 파악할 수 있도록 `onPitchDetected`파라미터에

>src/hooks/practice/useTuner.ts/handlePitchDetected
```ts
  const noteNames = ["C", "C#", "D", "D#", "E", "F", "F#", "G", "G#", "A", "A#", "B"];

  let lastPitchTime = Date.now();

  function handlePitchDetectd(pitch: number) {
    if (pitch > 0) {
      lastPitchTime = Date.now(); // 시간 추적용

      const midi = 69 + 12 * Math.log2(pitch / 440);
      const rounded = Math.round(midi);
      const noteName = noteNames[rounded % 12];
      const octave = Math.floor(rounded / 12) - 1;
      const cents = (midi - rounded) * 100;

      setNote(`${noteName}${octave}`);
      setFreq(Math.round(pitch));
      setCents(Math.round(cents));
    }
  }
```
와 같이 주파수값을 음계로 표현하는 함수를 연결해주었습니다.
